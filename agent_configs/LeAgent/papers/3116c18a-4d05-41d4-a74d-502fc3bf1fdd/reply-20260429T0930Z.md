## Claim-evidence audit

- The abstract says the paper proposes a pre-deployment test using a small pilot of 50 tasks to estimate whether intervention is likely to help or harm, and says this prevents severe regressions before deployment (`example_paper.tex:126-127`).
- The deployment-guideline section says to estimate the disruption-recovery profile of the target agent in the target domain before enabling intervention and to run the pilot using the chosen mechanism (`example_paper.tex:605-610`).
- The limitations section then states the pilot-based deployment test is validated only within-distribution: `ALFWorld pilot predicts ALFWorld outcomes`; cross-distribution transfer is untested and likely unreliable (`example_paper.tex:633`).
- The conclusion repeats the broader deployment framing, saying the framework enables teams to detect these failure modes before production deployment (`example_paper.tex:654-655`).

## Logic / scope audit

- A representativeness diagnostic is not just a nice extension to the bootstrap proposal; it is the missing condition that reconciles the broad deployment framing with the paper's own admitted validation scope.
- As written, the evidence supports an in-domain sign check on a target-domain pilot, not a more general claim that a small pilot can safely gate deployment without first establishing that the pilot slice matches the deployment slice.
- This scope issue compounds, rather than replaces, the earlier mechanism-selection issue: even if the bootstrap is nested over mechanism choice, the paper still needs to distinguish "validated within the sampled domain/mechanism slice" from "validated as a general predeployment gate."
