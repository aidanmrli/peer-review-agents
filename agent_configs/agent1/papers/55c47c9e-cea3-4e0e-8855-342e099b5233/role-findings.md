# DRTriton reproducibility findings

## Central claim and reproduction target

The paper claims that DRTriton trains a 7B model on 100k synthetic PyTorch programs, adds curriculum RL plus test-time search, and then achieves strong KernelBench speedups from a synthetic-data-only pipeline. The minimal reproduction target is not rerunning 100k-program training, but verifying that the released artifact exposes the concrete objects needed to replay or audit that pipeline.

## Paper and artifact evidence checked

- Koala tarball: `55c47c9e-cea3-4e0e-8855-342e099b5233.tar.gz`
- Top-level tarball contents: `main.tex`, `main.bib`, style files, figure PDFs/PNGs, `00README.json`
- `main.tex:317-323` states the headline system components and KernelBench claims.
- `main.tex:969-974` describes the final 2,026-pair SFT dataset built from 1,464 validated DeepSeek-R1 pairs plus 562 GPT-5.2 augmentations.
- `main.tex:1014-1065` describes the automatic PyTorch rewriting tool used to align KernelBench code with the training distribution.
- `main.tex:1117-1195` provides prompt text for evaluation, but no code package or external artifact link.
- `rg -n "https://|github|artifact|supplement" main.tex` returned no public code/data pointer in the manuscript body.

## Reproducibility result from the smallest meaningful check actually run

I unpacked the submission tarball and verified that it is manuscript-only. The bundle does not include:

- CSP-DAG synthetic program generator
- DeepSeek-R1 / GPT-5.2 data-generation scripts or manifests
- validation harness for PyTorch-Triton correctness filtering
- DRPO / curriculum training code
- automatic rewriting tool
- test-time search implementation
- synthetic benchmark or KernelBench run scripts

The only machine-readable metadata file (`00README.json`) identifies `main.tex` as the sole top-level source. This means the strongest empirical claims cannot currently be externally replayed from the public artifact surface.

## Implementation or correctness risks

- The paper’s core contribution is a pipeline, not just a theorem or analysis; without the pipeline code/manifests, external reviewers cannot check whether the reported 100k synthetic programs, 2,026-pair SFT set, rewriting stage, and search stage were implemented as described.
- The manuscript already contains internal reporting inconsistencies discussed by others (headline percentages, operator counts). Missing code makes those inconsistencies harder to resolve rather than easier.
- Because the training data is partly generated by external frontier models (DeepSeek-R1, GPT-5.2), reproducibility also depends on release of frozen intermediate data or exact prompts/manifests, not only training code.

## Novelty/framing context

This is a reproducibility limitation, not a direct refutation of the method. The system idea may still be strong. The missing release mainly caps confidence in the empirical headline until the executable artifact is identifiable and replayable.

## Decision impact

Negative update on reproducibility completeness. I can support a public comment stating that the current artifact does not let an external reviewer audit or replay the synthetic-data/RL/search pipeline behind the main results.
